# 설정 이전 도구 리팩토링

기준 스냅샷: `5150e7249a7003254b5fc4bd9512bdac93a0ac32`.

## 유지한 동작

16개 Number Pad 매핑, 매크로 2개, Codex 사용자 지정 단축키 13개, 전역 단축키 2개와 SVG 배치도는 변경하지 않습니다. 기존 Apply/Restore/Check 실행 파일 이름과 백업 저장 위치를 유지합니다. 새 `codex/Check.cmd`는 읽기 전용 확인용입니다.

## 변경 사항

- `shared/Settings.ps1`: JSON 읽기·최상위 단축키 편집·원자적 파일 교체·변경 감지·조건부 복구·백업 경로 검증을 공통화했습니다. 다른 JSON 속성을 다시 직렬화하지 않습니다.
- `codex/Transfer.ps1`: 명령 비교에 해시 집합을 사용해 병합 시 중첩 탐색을 없앴습니다. 파일 두 개를 저장하는 중 발생한 오류와 마지막 백업 메타데이터 오류도 조건부 복구 대상입니다. 새 백업에는 당시 적용한 전역 단축키도 기록하므로 나중에 배포 프로필이 바뀌어도 복구 판단 기준을 유지합니다.
- `windows/Transfer.ps1`: 적용 데이터를 `profile.json`으로 통일하고 ID·값 형식을 사전 검증합니다. 원본 매크로 해시는 한 번 계산해 재사용합니다. 복구에 필요한 백업 파일과 해시를 현재 레지스트리 삭제 전에 확인합니다. 적용 중 실패하여 앱샷 설정이 아직 원래 값인 경우도 복구할 수 있습니다.
- `windows/Windows-Shift.ps1`: 헤더, 길이, 종료값, 중복·0번 원본 스캔 코드를 검증합니다. 다른 키 변환을 보존하고 저장 직전의 변경 및 저장 후 전체 항목 수를 확인합니다.
- 동일 상태에 대한 재적용은 불필요한 쓰기와 백업 생성을 생략합니다. CMD 실행 파일은 PowerShell 실패 코드를 그대로 반환합니다.

`shared/`가 새 실행 의존성이므로 저장소 전체의 폴더 구조를 유지해 이전해야 합니다. 예전처럼 `windows/` 또는 `codex/`만 따로 복사하는 방식은 지원하지 않습니다.

## 검증과 한계

`tests/Run.Tests.ps1`은 외부 테스트 모듈 없이 실행되며 `tests/Windows.Tests.ps1`의 순수 함수 검사도 포함합니다. CI는 Windows PowerShell 5.1과 PowerShell 7을 사용합니다. 작업 과정의 테스트 결과는 GitHub Actions 실행 기록을 기준으로 확인합니다.

파일 교체는 각 파일 단위로 원자적이며, 두 파일 전체의 전원 장애 원자성을 보장하지 않습니다. 다른 프로세스의 비협조적인 쓰기를 완전히 잠글 수도 없습니다. 실행 전 앱 종료와 저장 직전 재확인을 함께 사용하고, 충돌 시 덮어쓰지 않습니다.

레지스트리·매크로 적용은 별도 복구 백업을 사용합니다. 자동 테스트는 실제 Number Pad 드라이버, UAC 및 재부팅 후 물리 키 입력을 검증하지 않습니다. 이전 버전에서 만든 백업은 기존 형식의 복구 정보가 있는 범위에서 읽으며, 해당 백업에 기록되지 않은 적용값은 기존 프로필을 참조할 수 있습니다.

실행 시간의 전후 벤치마크는 수행하지 않았습니다. 이번 최적화는 불필요한 쓰기·해시 재계산·반복 탐색을 줄이는 것이며 체감 속도 향상을 수치로 주장하지 않습니다.
